# 战略报告可执行性评估(存档)

> 这是对一份独立战略研究报告(出于敏感性仅本地保留、不纳入公开仓库)的可执行性评估,记录于立项讨论。作用:说明本仓**为什么**在某些地方偏离报告。

## 一、报告里扎实、可以直接当依据的部分

1. **战略重定位** —— 不和 GE/CFM 拼 fleet-scale 深度学习,做「本体 + 证据链 + 决策支持」层。全文最关键的判断,直接决定技术路线。「工程师副驾驶,不是自动放行官」把认证/安全风险降一个量级。
2. **小样本技术栈**(本体 + 物理残差 + self-supervised + active learning + weak supervision)—— 对稀有失效的航空场景是正确的组合。
3. **证据链 + PROV-O 溯源 + 不确定性一等公民 + ABSTAIN** —— 让系统可审计,是未来 condition-based maintenance credit 的前提。
4. **最短价值路径**:不改飞机,复用 ACARS/QAR 地面链路,先在地面加语义层。
5. **Shadow mode + stepped-wedge**(非 A/B)、按时间/ESN 隔离 split、precision-recall 而非 ROC-AUC、RUL 同时报 interval coverage —— ML 严谨性细节,多数团队会做错。
6. **Gold-label factory 是早期最有价值资产** —— 优先级判断正确。
7. **数据合规现实感**(PIPL、数据安全法、CAAC 民航数据管理办法、跨境)—— 相当到位。

## 二、报告里虚、有风险、不能照单全收的部分

1. **A1–A8 里有三个生死攸关**:A1(COMAC 数据合法使用权)、A2(1–2 家高利用率航司试点)、A3(LEAP-1C OEM 知识接口)。报告列为「假设」,但项目实际无法启动直到这几个有眉目。**结论:脚手架必须能在没有真实数据时推进** —— ingestion 走适配器抽象 + 合成数据源,工程不被数据准入卡死。
2. **「复用云诊/云析」是大假设**。这俩是 COMAC 内部生产系统,API/数据湖接口是否开放是最大工程阻塞点之一。脚手架不 hard-depend;用接口隔离 + mock 并行推进。
3. **技术栈表是菜单不是决策**。真实项目必须立项时选定一套。
4. **「双层图(OWL 权威 + 属性图视图)」有过工程风险**。报告自己也警告「漂亮 Dashboard」陷阱 —— 同样适用于「完美本体」。v0 只做单层。
5. **四脑之间的契约几乎没设计**。「LLM 只调用和解释」是原则,但 tool schema / Evidence schema / agent 状态机是空的 —— 这恰是脚手架最该先定义的。
6. **报告长于架构、短于「头 90 天具体做什么」**。脚手架补这一块。

## 三、本仓采纳的调整(已与立项人确认)

1. **Python-first 具体选型先锁**(见 ADR-0002)。
2. **垂直切片优先于水平分层**:EGT-margin 一个场景端到端打通(合成数据)。
3. **单层图 + 报告作强参考而非圣经**。
4. **Evidence 加显式三态 status**(见 ADR-0003)。
5. **配置/版本化/provenance 从 day1 内建**(事后补几乎不可能 —— 报告与本人一致)。

## 四、立项人确认的三个决策点

- 技术栈:认可 Python-first 选型 ✓
- 垂直切片:同意 EGT-margin 端到端打通 ✓
- 报告定位:采纳上述调整,报告作强参考 ✓
