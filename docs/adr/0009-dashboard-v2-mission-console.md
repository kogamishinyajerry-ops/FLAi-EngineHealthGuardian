# ADR 0009 — 看板 v2:任务控制台(渐进式披露 + 波形可视化)

- 状态:Accepted
- 日期:2026-08-12

## 背景
v1 看板(ADR-0008)把所有信息平铺在一张浅色监视页里,被指出:① 不是「设计」,只是信息罗列;② 应像游戏式监控台;③ 数据波动要可视化、让人一眼联想到问题;④ 正常项不该显示(按需展开);⑤ 航线数据如何被消化要显性。

## 决策
推翻 v1 的平铺,改为**深色「任务控制台」+ 渐进式披露**:

- **3 视图 IA**:机队总览(默认) / 航线流水 / 模型表现。顶栏场景 tab(EGT/振动)+ 子视图 tab。
- **异常优先**:默认只露 ADVISORY/ABSTAIN 卡(带状态 glow、琥珀脉冲);**正常机折叠**成「正常 · N 台」一行 dim 状态点。点任一引擎 → **详情抽屉**(侧滑,Esc/点遮罩关闭)。
- **数据可视化(无依赖,内联 SVG)**:
  - `charts.sparkline` —— 残差**波形**(折线+面积+阈值/基线参考线),波动形态直观传达「是否在恶化」。
  - `charts.radar` —— 4 维置信雷达(data/model/knowledge/applicability)。
- **航线流水视图**:动画管线 ACARS/QAR→译码→DQ→特征→规则→Evidence→gold-label,各阶段**计数**点亮;[▶重放] 触发光点沿管线流动(CSS keyframes)。
- **视觉语言**:深色 slate 底 + 冷青/蓝调;状态 glow(健康青绿、告警琥珀脉冲、拒答红辉);大号 glanceable 数字 + 等宽遥测字体。

## 为支持可视化补的数据层
- `core.evidence.Signal`(label/unit/points/baseline/threshold/flight_ids)+ `Evidence.signal` —— 残差序列本就是 Evidence 的依据,持久化它是诚实的,也让看板能画波形(之前只存聚合斜率,画不出波动)。
- `SliceResult.snapshots_in/clean` + demo 脚本写 `*_summary.json` 边车 —— 供管线视图的阶段计数。看板仍是**只读消费者**。

## 后果
- 好:一眼定位异常(正常项隐入背景);波动形态传达「发动机可能有问题」;航线数据消化过程可见;真·设计感。
- 代价:静态快照(改数据 `make dashboard` 重生成);波形是残差(非原始参数),阈值/基线是占位;无逐航段时间轴(后续可加)。
- 离线/零依赖/可复现不变(测试断言无 http 外链)。
